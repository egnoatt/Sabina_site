## Scopo e confini
- `/`: hero editoriale chiaro con illustrazione botanica puramente astratta, architettura delle sezioni più sobria, navigazione informativa verso biografia/formazione/blog.
- `/blog/[slug]`: layout editoriale e larghezza di lettura ridotta, titolazione serif, data e breadcrumb, Markdown e metadata esistenti conservati.
- `src/components/EditorialBotanical.tsx`: illustrazione SVG locale, senza fotografie, persona sintetica, richieste a terze parti né nuovi asset commerciali.
- `tailwind.config.js`: token `editorial.paper`, `editorial.mist`, `editorial.line`; `font-display` usa Georgia di sistema, body OpenSans locale invariato.
- `src/app/globals.css`: regole `editorial-prose` circoscritte agli articoli; link brand anziché il blu predefinito nella nuova pagina.
- `scripts/ux_smoke.py`: test browser dell'articolo oltre a test mobile/desktop esistenti.

**Non in scope:** `/chi-sono`, `/formazione`, menu, contenuti Markdown, pagina Privacy, CMS, contratto Vercel, DNS, novità cliniche, hosting e analytics. Design System v1.0 resta CURRENT; questa è una IMPLEMENTATION CANDIDATE v2.

## Principi
1. Sito **personale**, attività privata **chiusa**, zero pulsanti per prenotazioni.
2. Nome e testi esistenti valorizzati, evitando immagini della persona non autorizzate.
3. Decorazioni `aria-hidden`, gerarchia semantica, una sola `main`, navigazione da tastiera.
4. Token ed elementi geometrici ripetibili e mantenibili; niente dipendenze JS nuove, niente Google Fonts.
5. I testi degli **articoli Markdown sono identici alla baseline**: solo presentazione.
